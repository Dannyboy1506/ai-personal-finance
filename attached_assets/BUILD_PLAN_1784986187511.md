### Required UI States (previously missing)

- **Empty state** — new user / zero transactions: friendly prompt to add first account or transaction.
- **Loading state** — skeleton shimmer while Gemini Deep Audit runs (can take 1–3s).
- **Error state** — Tier 2/3 request failure: inline retry, doesn't block local logging.
- **Offline indicator** — persistent small banner when Tier 2/3 are unreachable; queued transactions shown with a count.

### DDL Table Definitions

```sql
-- Accounts Table
CREATE TABLE accounts (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    type TEXT NOT NULL,             -- 'BANK', 'CASH', 'CREDIT_CARD'
    currency TEXT NOT NULL DEFAULT 'USD',
    starting_balance REAL NOT NULL,
    current_balance REAL NOT NULL,
    is_deleted INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- Categories Table (keywords normalized out — see below)
CREATE TABLE categories (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    type TEXT NOT NULL,             -- 'EXPENSE', 'INCOME'
    is_risk_category INTEGER NOT NULL DEFAULT 0, -- e.g. Betting & Gambling
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- Category Keywords Table (normalized — indexable, queryable, learnable)
CREATE TABLE category_keywords (
    id TEXT PRIMARY KEY,
    category_id TEXT NOT NULL,
    keyword TEXT NOT NULL,
    source TEXT NOT NULL DEFAULT 'SEED', -- 'SEED', 'USER_CORRECTION', 'AI_LEARNED'
    weight REAL NOT NULL DEFAULT 1.0,
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE,
    UNIQUE(category_id, keyword)
);
CREATE INDEX idx_category_keywords_keyword ON category_keywords(keyword);

-- Budgets Table
CREATE TABLE budgets (
    id TEXT PRIMARY KEY,
    category_id TEXT NOT NULL,
    monthly_limit REAL NOT NULL,
    period TEXT NOT NULL,           -- 'MONTHLY', 'WEEKLY'
    rollover_enabled INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE
);

-- Goals Table
CREATE TABLE goals (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    target_amount REAL NOT NULL,
    current_amount REAL NOT NULL,
    target_date TEXT NOT NULL,
    is_deleted INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- Recurring Transaction Rules (subscriptions, salary, rent)
CREATE TABLE recurring_txn_rules (
    id TEXT PRIMARY KEY,
    account_id TEXT NOT NULL,
    category_id TEXT NOT NULL,
    amount REAL NOT NULL,
    type TEXT NOT NULL,             -- 'CREDIT', 'DEBIT'
    description TEXT NOT NULL,
    frequency TEXT NOT NULL,        -- 'WEEKLY', 'MONTHLY', 'YEARLY'
    next_run_date TEXT NOT NULL,
    is_active INTEGER NOT NULL DEFAULT 1,
    FOREIGN KEY (account_id) REFERENCES accounts(id) ON DELETE CASCADE,
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE
);

-- Transactions Table
CREATE TABLE transactions (
    id TEXT PRIMARY KEY,
    account_id TEXT NOT NULL,
    category_id TEXT NOT NULL,
    goal_id TEXT,                   -- Optional FK if transaction is a goal allocation
    recurring_rule_id TEXT,         -- Optional FK if generated from a recurring rule
    amount REAL NOT NULL,
    type TEXT NOT NULL,             -- 'CREDIT', 'DEBIT'
    description TEXT NOT NULL,
    timestamp TEXT NOT NULL,        -- ISO-8601 String
    processed_by TEXT NOT NULL,     -- 'ON_DEVICE', 'OPENROUTER', 'GEMINI', 'MANUAL'
    confidence REAL,                -- 0.0–1.0, null for MANUAL entries
    is_deleted INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (account_id) REFERENCES accounts(id) ON DELETE CASCADE,
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE,
    FOREIGN KEY (goal_id) REFERENCES goals(id) ON DELETE SET NULL,
    FOREIGN KEY (recurring_rule_id) REFERENCES recurring_txn_rules(id) ON DELETE SET NULL
);
CREATE INDEX idx_transactions_timestamp ON transactions(timestamp);
CREATE INDEX idx_transactions_category ON transactions(category_id);

-- Offline Sync Queue (for Tier 2/3 calls made while offline)
CREATE TABLE sync_queue (
    id TEXT PRIMARY KEY,
    raw_input TEXT NOT NULL,
    target_tier TEXT NOT NULL,      -- 'TIER_2', 'TIER_3'
    status TEXT NOT NULL DEFAULT 'PENDING', -- 'PENDING', 'FAILED', 'DONE'
    retry_count INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

**Key changes from the original schema:**
- `keywords` moved out of `categories` (was a JSON string, un-indexable) into its own `category_keywords` table — now queryable and able to accumulate learned keywords from user corrections.
- Added `created_at` / `updated_at` on every table for auditability and future sync support.
- Added `is_deleted` soft-delete flags on `accounts`, `goals`, `transactions` instead of hard deletes.
- Added `recurring_txn_rules` for subscriptions and salary so they don't require manual re-entry every cycle.
- Added `currency` to `accounts`.
- Added `rollover_enabled` to `budgets` to make rollover behavior explicit rather than assumed.
- Added `confidence` and `processed_by` to `transactions` so low-confidence parses can be flagged for user review.
- Added `sync_queue` to hold Tier 2/3 requests made while offline, so nothing silently fails.

## 🧠 3. Three-Tier Intelligence Engine Architecture

To eliminate paid API costs and stay strictly within free tier limits, transactions pass through a 3-tier processing pipeline.

```
                           ┌──────────────────────────────┐
                           │   User Input / Fast Log      │
                           │   "Spent 15 on Uber"         │
                           └──────────────┬───────────────┘
                                          │
                                          ▼
                         ┌─────────────────────────────────┐
                         │   Tier 1: On-Device Engine      │
                         │   Regex + Learned Keyword Map   │
                         └────────────────┬────────────────┘
                                          │
                          ┌───────────────┼───────────────────────────┐
                          │               │                           │
                   [High-confidence] [Low-confidence]          [No Match / Complex]
                          │               │                           │
                          ▼               ▼                           ▼
             ┌──────────────────┐ ┌──────────────────┐  ┌──────────────────────────────┐
             │ Instant Commit   │ │ Commit + prompt   │  │  Tier 2: OpenRouter Free     │
             │ (0ms, offline)   │ │ user to confirm   │  │  (Llama 3.3 70B free tier)   │
             └──────────────────┘ └──────────────────┘  └──────────────┬───────────────┘
                                                                        │
                                            [Correction feeds back into category_keywords]
                                                                        │
                                                               [Weekly Deep Review]
                                                                        │
                                                                        ▼
                                                         ┌──────────────────────────────┐
                                                         │  Tier 3: Google Gemini API   │
                                                         │  (gemini-2.5-flash)          │
                                                         └──────────────────────────────┘
```

| Engine Tier | Technology / Endpoint | Purpose & Target | Execution SLA |
|---|---|---|---|
| Tier 1: On-Device Engine | Native Dart + Local SQLite | Exact keyword parsing, regex extraction, credit/debit matching | 0ms (instant, offline) |
| Tier 2: Fast AI Fallback | OpenRouter (free-tier model) | Complex phrasing when Tier 1 has no confident match | ~500ms–1s, queued if offline |
| Tier 3: Reasoning Engine | Google Gemini 2.5 Flash | On-demand strategic audits, weekly risk reports, goal optimization | Manual / scheduled |

**Key changes from the original pipeline:**
- Tier 1 now returns a confidence score, not just a binary match/no-match — low-confidence matches still commit instantly (so the ledger stays real-time) but surface a one-tap confirmation chip in the UI.
- User corrections write back into `category_keywords` with `source = 'USER_CORRECTION'`, so the on-device engine actually improves over time instead of staying static.
- Offline Tier 2/3 requests write to `sync_queue` and retry on reconnect instead of silently failing.
- API keys are read from Android Keystore / `EncryptedSharedPreferences` at call time — never hardcoded or logged.

## 💻 4. Core Implementation Source Code

### A. Tier 1: On-Device Parsing Engine (`local_finance_engine.dart`)

```dart
class LocalFinanceEngine {
  final Database db; // Drift/SQLite handle
  LocalFinanceEngine(this.db);

  /// Parses text locally without making network or AI requests.
  /// Returns a result with a confidence score instead of a binary match.
  Future<Map<String, dynamic>?> parseLocally(String input) async {
    final cleanInput = input.toLowerCase().trim();

    // 1. Extract numerical amount
    final amountRegExp = RegExp(r'(\d+(?:\.\d{1,2})?)');
    final match = amountRegExp.firstMatch(cleanInput);
    if (match == null) return null; // Fallback to Tier 2 if no amount found
    final double amount = double.parse(match.group(1)!);

    // 2. Determine transaction type using stronger phrase boundaries,
    //    not naive .contains(), to avoid false positives like
    //    "got charged for uber" being read as a credit.
    final creditPatterns = [
      RegExp(r'\breceived\b'), RegExp(r'\bsalary\b'),
      RegExp(r'\bdeposit(ed)?\b.*\b(in|into|received)\b'),
      RegExp(r'\bgot paid\b'), RegExp(r'\badded\b.*\bto (my|account)\b'),
    ];
    final debitOverrides = [RegExp(r'\bcharged\b'), RegExp(r'\bspent\b'), RegExp(r'\bpaid\b.*\bfor\b')];
    final bool isCredit = creditPatterns.any((p) => p.hasMatch(cleanInput))
        && !debitOverrides.any((p) => p.hasMatch(cleanInput));
    final String type = isCredit ? 'CREDIT' : 'DEBIT';

    // 3. Match against learned keyword table (category_keywords), weighted
    final rows = await db.customSelect(
      'SELECT category_id, keyword, weight FROM category_keywords ORDER BY weight DESC',
    ).get();

    String? matchedCategory;
    double confidence = 0.0;
    for (final row in rows) {
      final keyword = row.read<String>('keyword');
      if (cleanInput.contains(keyword)) {
        matchedCategory = row.read<String>('category_id');
        confidence = row.read<double>('weight').clamp(0.0, 1.0);
        break;
      }
    }

    if (matchedCategory == null && !isCredit) {
      return null; // Pass through to Tier 2
    }

    return {
      'amount': amount,
      'type': type,
      'category_id': isCredit ? 'cat_income' : matchedCategory,
      'description': input,
      'processed_by': 'ON_DEVICE',
      'confidence': isCredit ? 0.9 : confidence,
      'needs_confirmation': !isCredit && confidence < 0.7,
    };
  }

  /// Called when the user corrects a parsed category — reinforces future parsing.
  Future<void> learnFromCorrection(String keyword, String correctCategoryId) async {
    await db.customStatement(
      '''INSERT INTO category_keywords (id, category_id, keyword, source, weight)
         VALUES (?, ?, ?, 'USER_CORRECTION', 1.0)
         ON CONFLICT(category_id, keyword) DO UPDATE SET weight = MIN(weight + 0.1, 1.0)''',
      [Uuid().v4(), correctCategoryId, keyword.toLowerCase()],
    );
  }
}
```

async function parseTransactionFast(userInput, getApiKey) {
  const apiKey = await getApiKey(); // e.g. reads from Android Keystore-backed store

  const prompt = `
  You are an ultra-fast bank transaction parser. Convert this user text into JSON.
  User Input: "${userInput}"

  Allowed Categories:
  - "Money In" (CREDITS: Salary, Refunds, Transfers)
  - "Transport" (Uber, Fuel, Bus)
  - "Betting & Gambling" (Bet9ja, Stake, Lottery, Casino)
  - "Groceries & Food" (Supermarkets, Fast Food, Dining)
  - "Bills & Utilities" (Airtime, Data, Electricity)
  - "Shopping & Lifestyle" (Tech, Clothes)
  - "General Expenses" (Fallback)

  Return ONLY valid JSON:
  { "type": "CREDIT" or "DEBIT", "amount": number, "category": string, "description": string, "confidence": number }
  `;

  try {
    const response = await fetch("https://openrouter.ai/api/v1/chat/completions", {
      method: "POST",
      headers: {
        "Authorization": `Bearer ${apiKey}`,
        "Content-Type": "application/json",
        "HTTP-Referer": "https://localhost",
        "X-Title": "FintechApp"
      },
      body: JSON.stringify({
        model: "meta-llama/llama-3.3-70b-instruct:free",
        response_format: { type: "json_object" },
        messages: [
          { role: "system", content: "You are a strict JSON extraction engine." },
          { role: "user", content: prompt }
        ]
      })
    });

    if (!response.ok) throw new Error(`OpenRouter error: ${response.status}`);
    const data = await response.json();
    return JSON.parse(data.choices[0].message.content);
  } catch (error) {
    console.error("Fast Parsing Error:", error);
    // Caller is responsible for writing this input to sync_queue for retry.
    return null;
  }
}

async function runGeminiDeepAudit(weeklySummaryJson, getApiKey) {
  const apiKey = await getApiKey();
  const url = `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent?key=${apiKey}`;

  You are a senior financial manager embedded in a personal mobile wallet.

  1. Identify high-risk impulse categories (especially Betting or Transport spikes).
  2. Provide 2 realistic micro-adjustments to boost savings toward active goals.

  `;

  try {
    const response = await fetch(url, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        contents: [{
          parts: [
            { text: systemInstruction },
            { text: `Weekly Summary Data:\n${JSON.stringify(weeklySummaryJson)}` }

        }]
      })
    });

    if (!response.ok) throw new Error(`Gemini error: ${response.status}`);

    return data.candidates[0].content.parts[0].text;
  } catch (error) {
    console.error("Gemini Audit Error:", error);
    return "Unable to perform deep audit right now. Please check your connection or try again later.";
  }
}

## 📊 5. High-Performance SQL Analytics Engine

Compute all statistics, burn rates, and net worth calculations locally instead of passing raw transaction histories to cloud servers.

### 1. Monthly Budget Burn Rate (with rollover support)

```sql
SELECT
    b.id AS budget_id,
    c.name AS category_name,
    b.monthly_limit
        + CASE WHEN b.rollover_enabled = 1
               THEN COALESCE((
                   SELECT b.monthly_limit - COALESCE(SUM(t2.amount), 0.0)
                   FROM transactions t2
                   WHERE t2.category_id = c.id AND t2.type = 'DEBIT' AND t2.is_deleted = 0
                     AND t2.timestamp >= date('now', 'start of month', '-1 month')
                     AND t2.timestamp < date('now', 'start of month')
               ), 0.0)
               ELSE 0.0 END AS effective_limit,
    COALESCE(SUM(t.amount), 0.0) AS total_spent,
    ROUND((COALESCE(SUM(t.amount), 0.0) / b.monthly_limit) * 100, 1) AS spent_percentage
FROM budgets b
JOIN categories c ON b.category_id = c.id
LEFT JOIN transactions t ON t.category_id = c.id
    AND t.type = 'DEBIT' AND t.is_deleted = 0
    AND t.timestamp >= date('now', 'start of month')
GROUP BY b.id;
```

### 2. Multi-Account Net Worth Aggregation

```sql
SELECT SUM(current_balance) AS total_net_worth
FROM accounts
WHERE is_deleted = 0;
```

### 3. Goal Pacing (new — powers the 🟢/🟡/🔴 indicator)

```sql
SELECT
    id,
    name,
    current_amount,
    target_amount,
    target_date,
    julianday(target_date) - julianday('now') AS days_remaining,
    (target_amount - current_amount) /
        NULLIF((julianday(target_date) - julianday('now')), 0) AS required_daily_rate
FROM goals
WHERE is_deleted = 0;
```

## 🛠️ 6. System Execution Workflow

1. **Onboarding & Schema Initialization**
   Initializes local SQLite tables and seeds `category_keywords` (e.g., `uber`, `fuel`, `bet9ja`, `food`) with `source = 'SEED'`.

2. **Multi-Stage Transaction Parsing**
   - **2A (On-Device):** `LocalFinanceEngine` attempts parsing. High-confidence matches commit instantly at 0ms with zero network use. Low-confidence matches commit instantly but surface a confirmation chip.
   - **2B (AI Fallback):** If unmatched, the string is sent to Tier 2 (OpenRouter). If offline, it's written to `sync_queue` and retried on reconnect.
   - **2C (Learning):** Any user correction — from a confirmation chip or a manual edit — is written back into `category_keywords`, improving future Tier 1 accuracy.

3. **Local Balance & Budget Commit**
   Committed atomically: deducts/credits `accounts.current_balance`, updates `budgets` spend metrics, recalculates `goals` allocations and pacing.

4. **On-Demand Gemini Strategic Audit**
   On request or scheduled weekly trigger, SQL-aggregated metrics (burn rate, net worth, goal pacing) are packaged into a lightweight JSON payload and sent to Gemini 2.5 Flash for guidance.

5. **Recurring Transactions** *(new)*
   A background job checks `recurring_txn_rules.next_run_date` daily; due rules auto-generate a transaction and advance `next_run_date`, so salary/subscriptions don't require manual re-entry.
